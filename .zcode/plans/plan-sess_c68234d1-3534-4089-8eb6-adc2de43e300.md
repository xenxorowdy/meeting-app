# Zoom / Google Meet metadata extension + unscheduled-call record prompt

## Context

A Chrome MV3 extension already exists at `apps/extension` ("Alpha Meeting Names"). It observes Google Meet / Zoom **web** DOM and POSTs `{participants, speaking, source, self}` to `POST /api/session/participants`, which the backend already uses to attribute transcript speakers. This plan extends it (plus backend, UI, and a small macOS helper) to add:

1. **Meeting finished / you left / dropped out** → auto-stop recording & summarize, with an **8s rejoin grace** (user-confirmed; leaving while others continue also stops).
2. **Mic muted in the meeting client** → mic is not recorded and mic audio is not sent to transcription; unmuting resumes automatically.
3. **Unscheduled call detection** → when a call starts that is not on the calendar (browser meeting via extension, or any app opening the mic on macOS via a native helper), show a notification; **clicking it starts recording immediately** (user-confirmed).
4. Active-speaker metadata keeps flowing through the existing path (contract unchanged).

All API/event changes are **additive** — no existing event names, payloads, or storage formats change.

## 1. Extension (`apps/extension`)

### `src/content/meet.js` / `src/content/zoom.js` — new profile hooks
- `micMuted()` → `true | false | null` (null = unknown, don't report).
  - Meet: toolbar mic button state (aria-label like "turn on microphone" ⇒ muted; `aria-pressed`). Zoom web: mic button aria-label ("Unmute" action available ⇒ muted) / audio-status icon on self tile.
- `ended()` → `null | { reason: 'ended' | 'left' }`.
  - Meet: "You left the meeting" / "Rejoin" / "Return to home screen" / "This call has ended" screens, or the in-call container gone while still on `meet.google.com`.
  - Zoom: post-leave feedback screen / meeting container removed while still on the meeting URL.

### `src/content/observer.js`
- Extend the payload with `micMuted`, `ended`, `reason`, `endedAt`.
- Poll loop: evaluate the new hooks each 700ms tick. **Bypass the heartbeat dedupe** (`sameObservation` + 2500ms gate at observer.js:205) whenever `micMuted` flips or `ended` becomes true — state changes ship immediately.
- Remove the early-return when `participants.length === 0` (observer.js:193) so ended/mute reports still send from post-leave screens (roster is empty there).
- `pagehide` listener: best-effort immediate report `{ended: true, reason: 'tab-closed'}` (backend watchdog is the backstop if it doesn't land).

### `src/background.js`
- Keep the `inflight` gate from swallowing terminal reports (never drop an `ended:true` message when busy); new fields pass through verbatim.

### `README.md` — document the new signals.

## 2. Backend (`apps/core-backend/src/main.rs`)

### `observe_participants` (main.rs:1156) — accept new fields + idle detection
- Parse `micMuted: Option<bool>`, `ended: Option<bool>`, `reason: Option<String>`.
- New session state: `client_mic_muted: Option<bool>`, `client_last_seen: Instant` (touched on every observation), `pending_client_end: Option<{source, reason, deadline}>`, `last_unscheduled_notice: Option<{key, at}>`.
- On mic-mute **change**: broadcast new WS event `mic_muted {meetingId, source, muted}`.
- On `ended: true` while Recording/Paused:
  - Broadcast new WS event `meeting_ended {meetingId, source, reason}`.
  - If setting `autoStopOnMeetingEnd` (new, default true): arm the 8s grace. UI stopping within grace (session leaves Recording) → cancel; fresh observation with `ended != true` (rejoin) within grace → cancel; grace expiry while still Recording → self-finish via existing `finish()` (same as stop with no recording; `meeting_completed` already broadcasts).
- **Idle meeting detection** (for the unscheduled-call prompt): currently the handler early-returns when there's no current meeting. Change it to first emit, when IDLE and roster non-empty, a deduped WS event `unscheduled_call {source, url, participants}` — one per source+url per 10 minutes — then return the existing `{accepted: false, state}` payload.
- `ended` while idle: no-op.

### Dropout watchdog
- While Recording **and at least one participant observation was received** (`participantSource` set): if `now - client_last_seen > 15s` → `meeting_ended` with `reason: 'dropout'` → same grace flow. Never armed without prior observations, so recordings made without the extension are never auto-stopped. Tokio interval task spawned when recording starts (pattern follows `consume_live_events`).

### Mute gating in `feed_audio` (main.rs:1016)
- When `client_mic_muted == Some(true)`, drop mic-stream PCM before it reaches the live transcriber / VAD / voiceprints (defense in depth behind the UI no-send below). Metering unchanged.

### Settings & status
- Add `autoStopOnMeetingEnd: bool` (default true) and `promptForUnscheduledCalls: bool` (default true) to the settings struct + `GET/POST /api/settings` round-trip.
- `GET /api/status`: include `clientMicMuted` and pending-end state for observability.

### Rust unit tests (patterns at main.rs:2952+)
- New payload fields parse; `mic_muted` broadcast on change only; `ended` while idle is a no-op; idle observation emits `unscheduled_call` once per cooldown; grace cancel on stop/rejoin; watchdog only fires when observations existed.

## 4. Unscheduled-call record prompt

### Native mic watcher (macOS)
- `apps/desktop/mic-watch/main.swift`: single-file Swift helper using CoreAudio — property listener on the default input device for `kAudioDevicePropertyDeviceIsRunningSomewhere` (the "any process has the mic open" signal behind macOS's orange dot); prints `active` / `inactive` lines on transitions; exits when stdin closes. Build script `npm run build:mic-watch` (swiftc → `apps/desktop/assets/mic-watch`), following the existing `SystemAudioDump` helper pattern (`apps/desktop/systemAudio.js`).
- `apps/desktop/micUsage.js`: Electron-main module (pattern from `systemAudio.js`) that locates/spawns the helper, **debounces** (mic open ≥ 8s → call-like, filters Siri/dictation blips), macOS-only availability with graceful no-op elsewhere, forwards transitions to the renderer over a new IPC channel `mic-usage:event {active}`. Registered in `main.js` alongside `systemAudio.registerHandlers()`; exposed in `preload.js` as `alphaMicUsage.onEvent(cb)`.

### Prompt coordinator (UI)
- New small hook `useUnscheduledCallPrompt`: single coordinator for both sources —
  - WS `unscheduled_call` events (browser meetings, via useMeetingSession) and `alphaMicUsage` IPC events (any app opening the mic).
  - Gates: session state must be IDLE (suppresses Alpha's own mic use during recording/pause), setting `promptForUnscheduledCalls` on, **no calendar event covers now** (existing `eventForNow` in `apps/ui/src/lib/calendarEvents.js`), shared cooldown (~5 min per source; browser dedupe handled backend-side per URL/10 min).
  - Fires an OS Notification "Unscheduled call detected — click to start recording" (pattern from `useMeetingReminder`, `notifications` permission already granted in `main.js:176`). Title/body derived from source: "Google Meet call" / "Zoom call" / "Call using your microphone".
  - Click → existing `handleStartRecording(title)` in `App.jsx` (line 215) — capture starts immediately with default devices, same path as the calendar reminder click.

## Limitations (documented, not fixed here)
- Zoom support covers the **web client** (`*.zoom.us/wc`, `*.zoomgov.com`) only — the extension cannot read the Zoom desktop app; the mic watcher catches desktop-app calls for the *prompt*, but speaker/mute/end metadata needs the web client.
- Mic-open detection can't tell a call from other sustained mic use (e.g., a voice memo); the 8s debounce + notification (no auto-start) keeps it non-intrusive.
- The extension reports to the local backend on `127.0.0.1:48900` (unchanged behavior).
