# Pricing, Plans, and Payments (Stripe + Razorpay) — Implementation Plan

## What exists today
- `GET /api/plans` (`apps/core-backend/src/plans.rs`) serves a catalog with Free (Local) + Pro marked "coming soon", price only from env vars, `billingEnabled: false`.
- `POST /api/billing/checkout` is a hardcoded 503 (`main.rs:2199`); `/api/license/status` is a stub returning free tier.
- UI already has a **Plans & pricing** tab: `PricingView.jsx` + `lib/plans.js` + `design.css` styles.
- Docs: `docs/PRODUCT-SETUP.md` "Pricing" section, `production_ready.md` checklist.

## Decided pricing (per user)
| Plan | India | Global | Notes |
|---|---|---|---|
| Free | ₹0 | $0 | 1 hour (60 min) recording/month, **no AI**, local workspace |
| Pro | ₹800/user/month (Razorpay, INR) | $10/user/month (Stripe, USD) | Unlimited recording, AI summaries, all features |
| Enterprise | Custom | Custom | "Contact sales" (mailto) — no self-serve checkout |

Checkout provider is chosen by the user on the pricing page via an India/Global region toggle (no IP geolocation).

## Backend (Rust, `apps/core-backend`)

### 1. `plans.rs` — new catalog
- 3 plans. Pro carries both region prices: `[{currency:"INR", amountMinor:80000, provider:"razorpay"}, {currency:"USD", amountMinor:1000, provider:"stripe"}]`. Env overrides (`ALPHA_PRO_MONTHLY_MINOR`/`ALPHA_BILLING_CURRENCY`) remain as overrides.
- Enterprise: `status:"contact"`, note to contact sales.
- `billingEnabled` = true only when provider keys are configured.

### 2. New `billing.rs` module (subscriptions + provider calls)
- SQLite tables in the existing accounts DB: `subscriptions` (account_id, plan, provider, provider_subscription_id, customer_id, status, currency, amount_minor, current_period_end), `billing_events` (provider, event_id unique → idempotency log).
- Keys via the existing credentials/env pattern (never committed, never sent to UI): `ALPHA_STRIPE_SECRET_KEY`, `ALPHA_STRIPE_PRICE_USD`, `ALPHA_STRIPE_WEBHOOK_SECRET`, `ALPHA_RAZORPAY_KEY_ID`, `ALPHA_RAZORPAY_KEY_SECRET`, `ALPHA_RAZORPAY_PLAN_INR`, `ALPHA_RAZORPAY_WEBHOOK_SECRET`.
- **`POST /api/billing/checkout`** (session required): body `{plan:"pro", currency:"INR"|"USD"}`.
  - USD → Stripe Checkout Session (mode=subscription) via reqwest; returns `{checkoutUrl}` (client redirects).
  - INR → Razorpay Subscription create; returns `{subscriptionId, keyId}` (client opens Razorpay checkout modal).
  - Unauthenticated/hosted-without-session → 401; missing keys → 503 with actionable message.
- **Webhooks**: `POST /api/billing/webhook/stripe` and `.../razorpay` — HMAC signature verification against raw body (bypass the JSON pre-parse for these two paths), handle subscription activated/renewed/cancelled/payment-failed, upsert `subscriptions`, idempotent via event id. Must be reachable without workspace deployment token but logged/auditable.
- **`GET /api/billing/subscription`** — current session's subscription + effective tier.
- Entitlement: effective tier = "pro" if an active subscription row exists for the session's account, else "free". Anonymous/local = free.

### 3. Free-tier enforcement (real, both rules)
- **60 min/month recording cap**: compute current-month recorded minutes from existing meeting storage (durations already persisted with `durationSeconds`/`startedAt`) — no new usage table. Gate `POST /api/meetings/start`: free tier over 60 min/month → 402 with message "Monthly free limit reached (1 hour). Upgrade to Pro…". Pro → unlimited.
- **No AI on free**: gate the managed summarizer (both auto-summarize at meeting finish and manual summarize) — free tier gets a clear "AI summaries require Pro" error instead of a summary. ⚠️ Behavior change: this applies to local/no-account users too (they are the free tier), including today's BYOK users.
- Update `/api/license/status` stub to report real tier, `canRecord`, minutes used/remaining, `billingEnabled`.

## Not in scope (stated, not silently dropped)
- Per-user seat pooling / team billing (app is one shared workspace; one subscription = one account/seat).
- Customer billing portal, proration, refund flows (webhook cancellation only).
- New Rust crates beyond what Stripe/Razorpay REST needs (reqwest already present).
