# Productionize the app: hosted backend + modern client

Six work areas. The client already speaks "hosted backend" (Connection tab, bearer tokens, HTTPS-only remote URLs) and `security.rs` already defines hosted mode — the missing pieces are enforcement in the request path, deployment artifacts, Whisper cleanup, and the UI type/polish pass.

## 1. Wire hosted security into the request path (deploy blocker)

`apps/core-backend/src/main.rs` — `handle_connection`/`read_http_request`:

- Header limit in `read_http_request` (currently 1 MB) → `security::MAX_HEADER_BYTES`; body capped at `MAX_BODY_BYTES` → 413 JSON.
- Host-header check via `security.host_allowed` (DNS-rebinding guard) → 403.
- Origin check: requests carrying a disallowed `Origin` → 403 (HTTP and WS).
- Auth: `/health` and `OPTIONS` preflight stay open; every other route requires `security.authorized(headers, false)` (Bearer token) → 401 JSON. The UI already sends these headers and already renders 401 messages.
- CORS: replace the hardcoded `Access-Control-Allow-Origin: *` (main.rs:1548) with an echo of the request Origin when it passes the allowlist, plus `Vary: Origin`; preflight returns allowed methods/headers.
- WebSocket `/ws`: validate the `alpha-token.<base64url>` subprotocol via `security.authorized(headers, true)` before the 101 handshake; echo `Sec-WebSocket-Protocol: alpha` in the response.
- Extract the gate into a unit-testable function; add Rust tests: no token → 401, valid token → pass, bad origin → 403, rebinding host → 403, `/health` open, oversized body → 413.

## 2. Deployment artifacts (Fly.io)

- `apps/core-backend/Dockerfile`: multi-stage (rust builder with prebuilt ort binaries → `debian:bookworm-slim`), `ca-certificates`, non-root user, `ENV ALPHA_DATA_DIR=/data CORE_BACKEND_HOST=0.0.0.0`, `VOLUME /data`, `EXPOSE 48900`.
- `apps/core-backend/.dockerignore` (target/, `.alpha-meeting-assistant/`, `.env`).
- `apps/core-backend/fly.toml`: internal_port 48900, `/health` healthcheck, 5 GB persistent volume at `/data` (meeting library, credentials, and the ~500 MB embeddings model downloaded on first chat use).
- `DEPLOYMENT.md` at repo root: fly deploy walkthrough; generating `ALPHA_BACKEND_TOKEN` (`openssl rand -base64 48`); `fly secrets set` for `ALPHA_GEMINI_API_KEY` / `ALPHA_SARVAM_API_KEY` / `ALPHA_ALLOWED_ORIGINS`; web-client section (build UI with `VITE_BACKEND_URL`, add its origin to the allowlist, paste token in Settings → Connection); local dev unchanged.
- `.github/workflows/ci.yml`: cargo test + UI build + node tests.

## 4. Readable type scale + a Text size setting that works

`apps/ui/src/design.css` + `apps/ui/tailwind.config.js`:

- Bump reading surfaces ~1–2px: chat bubbles 12→13.5px (roomier line-height), chat header 13→14px, empty-state heading 13→15px, starter cards 11→12px, citation chips 10→11px, coverage/meta lines 10→11px; same treatment for transcript/notes/summary surfaces; tailwind `footnote` token 11→12px.
- Make Personal → Text size functional: `:root[data-text-size='large']` rules that scale chat, transcript, and notes text (preferences.js already sets the attribute — today nothing consumes it).
- Honor `:root[data-reduced-motion='true']` alongside `prefers-reduced-motion`.
